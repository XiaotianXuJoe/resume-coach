## 评价维度（每项 0-100 分）
1. 内容完整性：教育背景、技能、项目/测试实践、实习等必要板块是否齐全
2. 量化表达：是否有量化指标（用例数、缺陷发现数、自动化覆盖率、回归耗时降低、压测指标 TPS/RT）
3. 岗位匹配度：技术栈与测试岗位的匹配程度（测试理论与用例设计、Linux/SQL、接口/自动化/性能测试、pytest/Selenium/JMeter、一门编程语言）
4. 项目深度：是否有真实测试实践（独立设计用例、搭建自动化框架、定位过疑难 Bug），还是只写"参与了测试"
5. 表达与结构：排版逻辑、措辞专业度、篇幅控制

## 测试方向简历的常见病（逐条检查，命中即指出）
- 把"测试"写成"点点点"：只写功能测试执行，没有用例设计方法和思考
- 技能栏写"熟悉自动化测试"但项目里没有任何框架、覆盖率等佐证
- 只罗列工具名（JMeter、Selenium、Postman），没有使用场景和产出
- 测试项目没有量化结果：发现多少 Bug、自动化节省多少回归时间
- 编程能力只字不提——测试开发岗必须体现代码能力（Python/Java + 脚本/平台开发）
- 与开发岗简历模板混用，突出"开发功能"而非"保障质量"的视角
