2. 量化表达：项目是否有量化指标（QPS、响应时间、数据量、并发量、性能提升百分比）

## Java 后端简历的常见病（逐条检查，命中即指出）
- 堆砌技术名词：技能栏写"熟悉 Redis"但项目中没有任何使用佐证
- 秒杀/商城/博客项目同质化严重，没有差异化亮点
- 项目描述只有功能罗列（"实现了登录、下单功能"），没有技术决策和难点
- "熟悉/精通"用词不当，应届生写"精通"容易被面试官重点拷打
- 个人贡献边界模糊，团队项目分不清"我"做了什么
