2. 量化表达：是否有量化指标（指标体系搭建、报表覆盖业务方数量、分析驱动的业务提升百分比、AB 实验结论落地效果）
3. 岗位匹配度：技术栈与数据分析岗位的匹配程度（SQL、Excel/透视表、Python/pandas、统计学基础、Tableau/Power BI 等 BI 工具、指标体系与埋点）
4. 项目深度：是否有完整分析闭环（定义问题→取数→分析→结论→推动落地），还是只写"做了数据报表"
5. 业务理解：是否体现业务思维（漏斗、留存、RFM、异动归因），而非纯取数工具人
6. 表达与结构：排版逻辑、措辞专业度、篇幅控制

## 数据分析方向简历的常见病（逐条检查，命中即指出）
- 只写"熟练使用 SQL/Excel"但项目中没有任何取数与分析场景佐证
- 把数据分析写成"取数工具人"：只罗列跑报表、导数据，没有分析结论和业务影响
- 项目没有量化业务结果：分析报告被采纳后带来了什么提升完全没写
- 通篇技术栈堆砌（Hadoop、Spark、机器学习算法），却没有指标体系、AB 实验等分析方法论——这是数开/算法简历，不是数分简历

- 业务 Case 缺失：没有"DAU 下降归因""活动效果评估"这类完整分析项目
- 可视化部分只写工具名（Tableau/Power BI），没有看板服务了多少业务方、支撑了什么决策
